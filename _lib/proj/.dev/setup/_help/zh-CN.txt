安装已声明的开发工具并生成项目开发环境脚本。

用法:
  {{INVOCATION}}

当前 V0 处理 Bun、PowerShell、MSVC 与 Rust。安装位置:
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/bun/installs/<version>
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/pwsh/installs/<version>
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/msvc/installs/<channel>
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/rust/installs/<toolchain>

同时生成:
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/env.cmd
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/export/env.ps1
  SWAWKIT_PROJ_DATA_ROOT/modules/kernel/.dev/setup/_state.json

_state.json 是 .dev.setup provider 的可用性协议，记录输入 revision、发布 token 与
producer contract。需要受管开发环境的命令只在状态为 ready 且
协议匹配时加载 export；修改受管工具的版本、channel、mode 或 hash 后，Core 会先将
provider 标记为 unavailable，旧 setup 也不能覆盖新的状态。重新运行 setup 即可发布
当前输入；与开发环境无关的配置变化不会使该 provider 失效。

同一 Swaw Kit Home 下的入口共享经过校验的下载缓存:
  SWAWKIT_HOME/data/proj_cache/downloads

该命令不接受动态参数，也不修改用户或系统 PATH。
任何已启用但尚未实现的开发模块声明都会在下载前报错并终止。

Bun 支持精确版本或 latest。latest 只在首次 setup 时解析为精确版本；
选择记录在 .dev.setup 的 export/bun 中，重复 setup 不会隐式升级。
GitHub Release API 提供的 digest 可用时会用于校验。
可通过 {{COMMAND}} ..entry.env.bun.SWAWKIT_PROJ_BUN_SHA256 进一步锁定安装包；
未设置时只给出黄色提示，不阻塞安装。latest 不能与固定 SHA 同时声明；
需要固定 SHA 时应同时声明精确版本。

PowerShell 支持精确版本或 latest，语义与 Bun 相同：首次 setup 通过官方
GitHub Release API 将 latest 解析并锁定为精确版本，重复 setup 不会隐式升级。
Windows x64 资产名称随版本生成，GitHub digest 可用时会用于校验；也可通过
{{COMMAND}} ..entry.env.pwsh.SWAWKIT_PROJ_PWSH_SHA256 锁定精确版本的安装包。

MSVC 通过 Visual Studio channel 自动解析最新版 x64 工具链和 Windows SDK。
product manifest 以 channel 身份和实际内容哈希缓存；所有 VSIX、MSI、CAB
均使用微软 manifest 提供的 SHA-256 严格校验，
项目只需通过 {{COMMAND}} ..entry.env.msvc.SWAWKIT_PROJ_MSVC_CHANNEL 声明 channel，
不维护版本链接或 hash。

Rust 通过 rustup 安装到隔离的 CARGO_HOME/RUSTUP_HOME，不修改用户 PATH。
V0 使用 minimal profile，并默认安装 rustfmt；toolchain 可声明 stable、beta、nightly、
带日期的 channel，或具体版本。移动 channel 只在首次安装时解析；
重复 setup 不隐式升级健康工具链。
SWAWKIT_PROJ_RUST_TOOLCHAIN 是受管命令的权威声明；项目目录中的
rust-toolchain.toml 不会改变 .dev.cargo/.dev.rustc 选用的编译器，
并拒绝 cargo/rustc 的 +toolchain 临时覆盖。

setup 会识别上次中断遗留的 partial/backup：优先恢复有效备份；
没有有效备份时清理无效正式目录和中间目录，再执行干净安装。
文件仍被其他进程锁定时保留有效备份并明确报错，释放占用后重试即可。
